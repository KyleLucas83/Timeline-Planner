# Timeline Planner Roadmap

## Vision
Create a simple, reliable timeline planning experience that helps users organize future commitments, milestones, and agenda items without friction.

## Goals
- Make planning fast and intuitive
- Support both short-term and long-range scheduling
- Keep state reliable and easy to recover
- Support sharing and collaboration over time

## Status Legend
- Planned
- In Progress
- Done
- Paused

## Near-Term (0-3 months)
### Planned
- MVP timeline editor
- Event creation and editing
- Save/load plans
- Basic date validation
- Simple list and calendar view

### In Progress
- Drag-and-drop scheduling
- Recurring items
- Tagging and filtering

### Done
- Repository scaffolding and project setup
- Initial roadmap and documentation structure
- Core planner UI shell
- Theme selection and view toggles
- Event modal creation/editing flow
- Save, export, and import functionality
- Basic dirty-state tracking for unsaved work

## Mid-Term (3-6 months)
### Planned
- Event reminders
- Timeline export
- Reusable templates
- Calendar integration
- Multi-project planning

### In Progress
- Refined scheduling behavior and UX polish
- Data recovery and persistence improvements

## Long-Term (6+ months)
### Planned
- Shared collaboration
- Shared workspace permissions
- Smart recommendations
- Analytics and insights
- AI-assisted planning

## Definition of Ready
A task is ready to begin when:
- user value is clear
- acceptance criteria exist
- scope is narrow enough to deliver
- dependencies are identified
- success can be measured

## Definition of Done
A feature is done when:
- implementation is complete
- tests pass
- docs are updated
- release notes are added if needed
- UX is reviewed and confirmed

## Update Cadence
- Weekly: internal progress and blockers check
- Monthly: roadmap review and priority rebalancing
- Before release: update changelog and docs
- After release: capture wins, issues, and follow-up work

## Repository Governance
- Keep one source of truth for roadmap guidance in this document
- Update the roadmap when milestones change
- Link roadmap items to issue or task tracking when implementation starts
- Prefer small, reviewable deliveries over broad, undefined initiatives
