# Decision Log

This file records major product and engineering decisions for the project.

## Decision 1: Start with a simple, local-first planner
Date: 2026-10-25

Status: Accepted

Why:
- reduces initial complexity
- makes MVP iteration faster
- keeps timeline planning reliable and easy to validate

Impact:
- future sync and collaboration features can be layered on later
- data model should remain extensible from the start

## Decision 2: Use a roadmap-first development process
Date: 2026-10-25

Status: Accepted

Why:
- helps define milestones before implementation
- makes scope and priorities visible
- gives a clear workflow for delivery and review

Impact:
- features are grouped by milestone and readiness criteria
- roadmap updates are expected at regular intervals

## Decision 3: Keep docs active as the product grows
Date: 2026-10-25

Status: Accepted

Why:
- project clarity improves with architecture and decisions tracked over time
- onboarding is easier for new contributors
- release notes help maintain continuity across iterations

Impact:
- each milestone should update docs when relevant
- product decisions should be recorded as they are made
